# Headless / cron invocation

`scripts/run_headless.py <subcommand>` is the one entrypoint every scheduler calls. It
acquires a lock, builds the `claude -p` command below, captures the result, and exits
non-zero on failure so the scheduler's own failure handling (mail, `journalctl`, log
grep) works without parsing transcripts.

## The command

```sh
claude -p "/job-search scan --headless --run <uuid>" \
  --model opus --fallback-model sonnet \
  --permission-mode dontAsk \
  --settings "$JOBSEARCH_HOME/config/headless.settings.json" \
  --mcp-config "$JOBSEARCH_HOME/config/mcp.headless.json" \
  --strict-mcp-config \
  --disallowedTools "AskUserQuestion" \
  --max-turns 120 --max-budget-usd 4.00 \
  --session-id "<uuid>" \
  --output-format json \
  < /dev/null
```

| Flag | Why |
|---|---|
| `-p` | Non-interactive; exits 0/non-zero, never blocks on input. |
| `--permission-mode dontAsk` | Auto-denies anything not in `permissions.allow`; the documented CI mode. Also denies `AskUserQuestion` outright. |
| `--settings` | Loads the generated allowlist without touching `~/.claude/settings.json`. |
| `--mcp-config` + `--strict-mcp-config` | Loads exactly `firecrawl`/`playwright`/`notion`; ignores any stray server in `~/.claude.json`. |
| `--disallowedTools AskUserQuestion` | Belt-and-braces with `dontAsk`. |
| `--max-turns` / `--max-budget-usd` | Hard stop on a runaway board crawl or a billing runaway. |
| `--session-id <uuid>` | Correlates `memory/runs/<uuid>.json` with a resumable transcript; also the idempotence key (below). |
| `--output-format json` | Machine-readable `.result` / `is_error` / `num_turns` / `total_cost_usd`. |
| `< /dev/null` | Required on both platforms — without it Claude Code waits ~3s for stdin, warns, and (observed) can produce no output at all. cron and launchd attach a stdin; systemd services do not, but pass it anyway for consistency. |

**Do not add `--bare`.** It disables discovery of skills, hooks, MCP servers, and
CLAUDE.md — which removes `/job-search` itself — and it never reads OAuth credentials
or the system keychain, which breaks the OAuth'd Notion MCP server.

**Do not add `--dangerously-skip-permissions`.** `bypassPermissions` is documented for
isolated containers/VMs only. This run writes into a real, logged-in browser profile
(`config/browser-profile`); an explicit allowlist in `headless.settings.json` is the
whole point, not overhead to skip.

## Two verified gotchas

1. **A leading `select` verb eats two positional arguments.** The Claude Code
   positional tokenizer treats a leading `select` token as a shell `select NAME in …`
   compound and swallows it plus the next token — `$0`/`$1` end up wrong even though
   `$ARGUMENTS` stays correct. That is why the `/job-search` grammar uses **`pick`**,
   never `select`, as the sub-command verb.
2. **An injected `` !`command` `` containing a `$` aborts the whole invocation, and
   silently under `-p`.** The permission check rejects any surviving shell expansion
   with `Contains expansion`; the run then produces `num_turns: 0` and **exit code 0**
   — a cron job records a clean success and does nothing. The fix used throughout this
   skill: put environment-dependent logic in a script, invoke it by
   `${CLAUDE_SKILL_DIR}` path (substituted *before* the permission check, so the final
   string has no `$`), and pre-approve exactly that path:
   ```yaml
   allowed-tools: Bash(${CLAUDE_SKILL_DIR}/scripts/runtime_probe.py)
   ```
   `scripts/runtime_probe.py` is referenced this way in `SKILL.md`'s `!` injection —
   its own stdout is likewise `$`-free (checked by `tests/test_doctor.py`) so nothing
   it prints can trip the same check downstream.

## `mcp.headless.json`

Generated by `doctor.bootstrap` from `assets/mcp.headless.example.json` (absolute
paths substituted, `{{BROWSER}}` = `chrome` on macOS / `chromium` on Linux):

```json
{
  "mcpServers": {
    "playwright": {"command": "npx", "args": ["@playwright/mcp@latest", "--browser", "chrome",
      "--user-data-dir", "<home>/config/browser-profile", "--output-dir", "<home>/applications/_artifacts", "--save-session"], "timeout": 600000},
    "firecrawl": {"command": "npx", "args": ["-y", "firecrawl-mcp"], "env": {"FIRECRAWL_API_KEY": "${FIRECRAWL_API_KEY}"}, "timeout": 300000},
    "notion": {"type": "http", "url": "https://mcp.notion.com/mcp", "timeout": 120000}
  }
}
```

`notion` is declared explicitly rather than relying on a claude.ai connector, because
connector-style auth may be absent in headless runs. **Authorize it once, interactively,
per machine**, with `/mcp` inside a normal `claude` session before the first scheduled
run — the OAuth token then persists for subsequent `-p` invocations.

**Verifying MCP actually loaded:** an invalid server entry is skipped and the run
*exits cleanly* — a scheduled job can succeed with no browser at all. `run_headless.py`
runs `claude mcp list` once per run and warns on stderr if `firecrawl` or `playwright`
is absent from the output, rather than trusting silence.

## Scheduler templates

`assets/schedulers/{crontab.txt,launchd.plist,job-search.service,job-search.timer}`
ship with `{{HOME}}` (data home), `{{SKILL}}` (skill dir), and `{{HOME_DIR}}` (user
home) tokens **still in place** — unlike `headless.settings.json`/`mcp.headless.json`,
these are not rendered by `doctor.bootstrap`. Copy the template and replace the tokens
by hand (or have `setup` do it) before installing it with the OS scheduler.

- **cron (both platforms).** Lowest common denominator; its `PATH` is minimal, so the
  template sets it explicitly. **macOS:** `/usr/sbin/cron` needs **Full Disk Access**
  (System Settings → Privacy & Security → Full Disk Access) to read most user data,
  and runs outside the GUI session's Keychain unlock — prefer launchd there. **Linux:**
  a bare cron job has no D-Bus session/keyring agent, which matters if Claude Code's
  credentials live in a Secret Service keyring; verify with a manual run first.
- **launchd (macOS, recommended).** `launchctl bootstrap gui/$UID ~/Library/LaunchAgents/com.example.job-search.plist`
  — a `gui/$UID` agent has a live GUI session whenever the user is logged in, which a
  **headed** Chrome needs. `ProcessType Background` keeps it out of the foreground QoS
  band.
- **systemd user timer (Linux, recommended).** `systemctl --user enable --now
  job-search.timer`, then `loginctl enable-linger "$USER"` — **required** for the timer
  to fire with no active login session; without it, user units stop when the last
  session ends. `Persistent=true` in the `.timer` unit catches up a run that was missed
  while the machine was off.
- **Headless Linux server/container:** additionally set
  `JOBSEARCH_BROWSER_MODE=headless` (env in the `.service` unit, or exported before
  cron). `config.py` reads it as an override that forces Playwright's `--headless` and
  downgrades any ATS that needs a headed session straight to `needs_manual_apply`.

## Idempotence

A scheduled run can legitimately fire twice (manual + cron overlap, a missed-run
catch-up). Six cheap, platform-neutral mechanisms make that safe:

1. **Single-flight lock** — `memory/.run.lock/` via atomic `mkdir` (portable; `flock`
   is Linux-only) with stale-pid cleanup via `os.kill(pid, 0)`.
2. **Run id = `--session-id`** — every run writes `memory/runs/<uuid>.json`; a repeat
   of the same id is a no-op downstream.
3. **Upsert, never append-blind** — job writes go through `jobs_db.py upsert` keyed by
   `fingerprint`; a same-day rerun updates `last_seen` only.
4. **Cooldown deduplicates attention** — a job already shown within 14 days cannot
   re-enter a report even if the boards return it again.
5. **Atomic writes** — `common.atomic_write` (`tmp` + `os.replace`) everywhere.
6. **Reports are versioned** — `reports/<date>.md` is owned by the first run of the
   day; a second run writes `reports/<date>.r2.md`. `applications/<date>-<fingerprint>/`
   is inherently idempotent by directory name.
